# X thread draft (English)

1/ DSH ships fast. 39 releases since August, 10 prereleases in the last 30 days, and the README says compatibility-breaking changes are expected.

So when a plugin says "supports DSH", which version does it mean?

2/ We checked 44 DSH plugins. Only 24 declare `engines.dsh`. 20 are `unknown` — you cannot tell from metadata whether they cover the DSH version you run.

3/ That's why we built HCB: Host Compatibility Baseline.

It maps plugin-declared ranges to the last 10 DSH releases, and aggregates the capability surface (files, network, subprocess).

4/ v0.1 is live:
- 44 plugins × 10 hosts
- declared-compatible / declared-incompatible / unknown
- reproducible collector + JSON schema + Pages viewer

5/ Important: **declared ≠ tested**. A plugin can declare `>=0.2.0 <0.3.0` and still crash on `0.2.2-rc.3`. Tested matrix is v0.2, with Docker repro per cell.

6/ How to use it:
- before upgrading DSH: check if your plugins' ranges cover the target
- before installing: check the capability surface
- in CI: treat `declared-incompatible` as warning, `unknown` as info

7/ If you maintain a plugin: add one line, `engines.dsh`. It's the cheapest compatibility investment you can make.

8/ Not a ranking. Not a security audit. Not affiliated with DeepSeek. Independent community baseline.
